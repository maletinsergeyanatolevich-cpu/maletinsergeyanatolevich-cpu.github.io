## Единственная инструкция для первого шага

1. Откройте [Apps Script](https://script.google.com/home/projects/create) и создайте **НОВЫЙ ОТДЕЛЬНЫЙ проект**: `Q029 Wallet RH9 — READ ONLY PILOT`. Не открывайте существующий production-проект для этой операции.
2. Откройте [Code.gs](./Code.gs) в этой ветке GitHub, нажмите `Raw` или `Copy raw file`. Скопируйте весь файл (около 330 тыс. символов), замените стандартный `myFunction` в `Code.gs` **нового проекта**. Сохраните. Не запускайте вручную вспомогательные функции.
3. В **новом** проекте нажмите **Развернуть → Новое развертывание** (НЕ `Управление развертываниями → изменить` для существующего production).
4. Тип **Веб-приложение**; описание `Q029-RH9-READONLY-PILOT`; **Выполнять от имени: меня**; **Кому доступно: только мне** на первом шаге. Подтвердите нужные разрешения на чтение таблицы.
5. Откройте полученный адрес `/exec?action=ping` под своим аккаунтом Google. Должен вернуться JSON с `service: q029-wallet-isolated-readonly-pilot`, `version: backend-0.2.34-staging-q029`, `pilot_mode: READ_ONLY`, `build: 2026-10-12.q029.rh9`.
6. Пришлите скриншот результата ping (без токенов, кода авторизации и личных данных) и **URL нового тестового /exec**. На этом первом шаге остановитесь. PWA пока не публикуйте, production не обновляйте.

## Жёсткий шлюз

GET: только `ping`.

POST: только `ping`, `auth.check` с уже существующей сессией и `wallet.canonical.get` с реальной проверкой разрешения `wallet.view`. POST-ответы не записывают session/device touches; вход `wallet.canonical.get` вызывает `authSession_` и `q046BuildCanonicalWallet_` прямо, не вызывая штатный `handleWalletCanonicalGetQ046_` с техническими записями.

Все остальные действия, включая `access.request`, `access.activate`, `snapshot.pull`, `sync.domain.*`, `wallet.finance.create`, `reconciliation.apply` и `wallet.schema.migration.apply`, отклоняются **до диспетчеризации** с `Q029_PILOT_READ_ONLY_ACTION_DENIED`. Не менять список в ходе первого шага.

Пилотный код читает *существующую* каноническую таблицу `Финансы` для Wallet. Это **изоляция развертывания и запись-запрещённый API**, а не анонимизированная копия исходной таблицы. Никакие строки Finance и служебные HEAD не исправляются. До отдельной настройки isolated PWA обычный экран приложения и авторизованный ADMIN1/USER E2E НЕ пройдены.

Основной backend0.2.31, PWA v0.3.27.2, PR26, Finance106/_DOMAIN_HEADS116 и Q044 opening остаются нетронутыми. Тестовый домен PWA и работа с реальными браузерными сессиями — только следующий отдельный шаг после проверки `ping`; не перемещать реальные session tokens между профилями и не присылать их в чат.
