# Q-029: Wallet — изолированный просмотр владельца, без CORS

**Это следующий шаг ПОСЛЕ уже успешно открытого ping. Развёртывать только в существующем отдельном тестовом проекте `Q029 Wallet RH9 — READ ONLY PILOT`. НИКОГДА не изменять production Apps Script или его развертывание.**

Новый клиент обслуживается тем же отдельным Apps Script через `HtmlService` и безопасный `google.script.run`. Адрес отдельного /exec нигде в публичных исходниках не хранится и не публикуется. Это обход известного ограничения CORS между отдельным сайтом и Apps Script, а не изменение production.

## Шаги

1. Откройте **тот новый тестовый проект Apps Script**, который вы создали для подтверждённого ping `q029-isolated-readonly-pilot`. Проверьте его название. Не открывайте старый production Apps Script.
2. Откройте новый [Code.gs](./Code.gs) этой ветки `q029-rh9-readonly-wallet-browser-ui`, нажмите `Raw`, замените **полностью** Code.gs в том тестовом проекте.
3. Слева рядом с `Файлы` нажмите `+` → `HTML`, назовите **WalletPilot** (интерфейс создаст `WalletPilot.html`). Скопируйте весь [WalletPilot.html](./WalletPilot.html) из GitHub и вставьте целиком.
4. Сохраните проект. **Развернуть → Управление развертываниями → только тестовое Q029-развертывание → Изменить (карандаш) → Версия: Новая версия → Развернуть**. Сохраните доступ **«Только я»** и выполняется **«от моего имени»**. Ничего не менять в других проектах.
5. Под своим аккаунтом Google откройте тот же новый тестовый URL с `?action=ping`: результат предыдущей проверки должен остаться `ok:true`/`mode:READ_ONLY`.
6. В том же URL замените параметр на `?action=wallet-preview`, откройте страницу «Кошелёк — тестовый просмотр», нажмите `Загрузить Wallet`. Это реальный серверный read-only расчёт от имени Google-владельца тестового проекта, не настоящий логин ADMIN1/USER в PWA.
7. Пришлите скриншот с заголовком/статусом и счётчиками `finance_row_count`, `finance_head_row_count`; **суммы и хэши можно скрыть**. Если будет `Q029_PILOT_OWNER_NOT_CONFIRMED`, остановитесь и сообщите только этот код ошибки — не отключайте защиту и не расширяйте доступ.

## Ограничения и контроль

- Владельцем считается только учётная запись, где `Session.getActiveUser().getEmail()` совпадает с `Session.getEffectiveUser().getEmail()`. Если Google не раскрывает email, функция намеренно выдаёт запрет. Это безопаснее, чем показать частные данные неизвестному браузеру.
- Режим веб-приложения остаётся **«Только я»**. **Никогда не менять на «Все/Любой»**. Backend `doPost` по-прежнему разрешает только `ping` и `wallet.canonical.get` с текущим токеном приложения + `wallet.view`. Все остальные POST отклоняются. Дополнительный браузерный метод `q029PilotOwnerWalletRead` требует проверки именно Google-владельца и возвращает только агрегаты и служебные хэши, без истории транзакций или сессионных токенов.
- Штатные AUTH роли ADMIN1/USER, запрет без wallet.view, старая установленная PWA и кэш старого телефона **ещё не проверены**. Для них дальше будет отдельный контролируемый путь, без передачи паролей/токенов через чат.
- Публикация из этой ветки не касается PR#26/production: исходный SYS-подтвержденный backend rh9 pin `5f569d4a1f56acf9cea3daee3dd8bcfcc7b94269` неизменен. Источник `Финансы` 106 и `_DOMAIN_HEADS` 116 не исправлять из теста; Q044 открытие не менять.
- Все действия в этих файлах — чтение и отображение. Не устанавливать новые фоновые триггеры, не исполнять функции других проектов.

До завершения реального клиентского E2E Q029 остаётся `IN_PROGRESS`, production `NO-GO`.
