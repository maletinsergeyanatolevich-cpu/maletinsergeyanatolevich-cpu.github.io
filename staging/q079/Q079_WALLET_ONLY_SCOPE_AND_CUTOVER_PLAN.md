## Rollback

- **Before cutover:** ничего не откатывать, исходный `main`, GAS deployment и живой spreadsheet не меняются.
- **At cutover failure before first new-generation write:** снять Wallet2 write gate, откатить только wallet route/статический build и GAS deploy к зафиксированным версиям; исходные бизнес-строки восстанавливать **только** из верифицированного архива по явному согласованию, без автоматического replay старой очереди телефона.
- **After first new-generation write:** не включать старый финансовый backend как fallback (он восстановит старые суммы и может задвоить новые операции). Сначала заморозить Wallet2 writes; зафиксировать новый ledger и операции после switch; выполнить отдельное reconciliation / migration decision с владельцем; rollback app-code без возврата к старому финансовому dataset. Не удалять новые ledger entries, пока они не перенесены/урегулированы.
- При любой несогласованности архива, неверной generation, ошибке права, незавершённой транзакции, тестовом падении UX или отсутствии SYS QA — **NO-GO**, никакого cutover.
